### the problem

The old website had several problems.

Its design was outdated, it wasn't properly responsive, and pages could take a frustratingly long time to load.

Maintaining it was another headache. Even relatively straightforward changes were difficult, and the aging software introduced security concerns.

Rather than continuing to patch an increasingly troublesome system, I decided to build something new.

### what i built

**Taking the project from start to finish.**

I used Next.js, React, TypeScript, and Tailwind CSS to create a modern, responsive website.

**Keeping the architecture simple.**

For a company information website, that was a much more practical approach than maintaining a full WordPress installation.

**Automating deployment.**

Updates now follow a repeatable deployment process instead of requiring manual file management.

**Making it maintainable.**

I wanted someone else to be able to understand and work on the project without needing me to explain everything.

### the interesting bits

**Knowing when to start over.**

I don't think rewriting an existing system is always the right answer.

But sometimes the cost of maintaining something outweighs the cost of replacing it.

In this case, rebuilding the website gave me the opportunity to address its design, performance, maintenance, and security concerns together.

**Owning the whole thing.**

This project involved more than writing frontend code.

I had to make decisions about the design, technology, architecture, deployment, and long-term maintenance.

It was a good exercise in taking responsibility for an entire project rather than just one part of it.

### where things stand

The company now has a modern, responsive website with a simpler deployment model, automated releases, and documentation for future maintainers.

It's a smaller project than some of my backend and data infrastructure work, but it's one I took from beginning to end.
