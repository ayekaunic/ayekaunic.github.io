Not every project starts with a blank slate.

FRAMES is an internal application at Foresight Research that helps our teams manage and process household consumption data.

It's built with Flutter, Python/Flask, and SQL Server. By the time I started working on it, it was already an established part of the company's day-to-day operations.

When I started working on it, the application was already in production. People were using it to get their work done, and changing things meant being careful not to disrupt the workflows they relied on.

My job was to figure out how it worked and, gradually, make it easier for everyone else to work with.


I introduced GitHub Actions workflows to automate the release builds and integrated Nextcloud for distributing updates.

I established development conventions covering branch naming, commit messages, issues, pull requests, and code organization.

I also documented maintenance procedures and contribution workflows so that developers have a shared understanding of how changes should be made.

Alongside those changes, I've been gradually restructuring parts of the Flask backend and improving existing workflows.
